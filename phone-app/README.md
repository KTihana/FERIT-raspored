# FERIT raspored

## Android 1.0.18 — Danas home widget

The Android widget uses the approved translucent dark card with the actual FERIT vector, Inter type, a peach in-class progress bar, upcoming start times and rooms, and the refresh/calendar controls.

Install **FERIT-raspored.apk** from the [1.0.18 release](https://github.com/KTihana/FERIT-raspored/releases/tag/v1.0.18-android-test) over the previous app, then open **Postavke → Widget na početnom zaslonu**. If the launcher does not support the add dialog, long-press the home screen, open **Widgeti**, and choose **FERIT · Danas**. The widget uses the app's selected study, per-subject LV groups, repeating subjects and types, personal events, moves and removals. It can be resized; smaller sizes prioritize the current and next event.

Progress comes from the phone's current timestamp and the timetable's start/end times in Europe/Zagreb. A local minute update advances the bar while the screen is interactive. Screen-on/unlock also recalculates it, and an overdue non-waking alarm catches up after sleep. There are no progress redraws while the screen is off, no second-by-second app timer, foreground service or app-held wake lock. Clock changes and restarts rebuild the next update. Android calendar exact-alarm access is used for these local ticks, with an inexact fallback if unavailable; manufacturer battery restrictions can still delay delivery.

A separate persisted Android job checks the current week approximately every hour, including selected repeating-subject source schedules. Android may defer that network job in Doze or without connectivity. The refresh icon requests an immediate check and shows a status in the footer. Failed or invalid responses preserve the last successful cache and personal choices. All jobs and clock alarms are removed when the last widget is removed. Widget downloads also update the cache read by the main app.

Native code: `android/app/src/main/java/app/mojraspored/ferit/widget/`. Regenerate the layout and vector with `node scripts/widget-resources.mjs`. Generate parser parity fixtures with `node scripts/widget-test-fixtures.mjs`, then run `:app:testDebugUnitTest`. The instrumented widget tests exercise actual RemoteViews, sizing, screen-off/wake timing, hourly job configuration, manual refresh, and offline preservation on Android. These changes implement an Android home widget; the iPhone project has no widget extension.

The Android version is **1.0.18**, build **24**. The release includes the installable APK and complete source ZIP; the source is also available under `phone-app/` in the repository. The widget is Android-only.

## Download on your Android phone

Open [the Android test release](https://github.com/KTihana/FERIT-raspored/releases/tag/v1.0.18-android-test) and download **FERIT-raspored.apk** under Assets. Open the downloaded APK to install it. Install it over the previous version to keep your saved choices and personal changes. This signed development build awaits real-phone testing.

The Android app checks GitHub for updates. You can also use **Provjeri ažuriranja** in **Postavke**. Download the APK and confirm installation on the phone; Android updates are not installed silently.

The complete Android/iPhone source project is included as **FERIT-raspored-source.zip**. Extract it on a computer to build or edit the app.

This folder is the standalone Android and iPhone project. The interface, fonts and icons are bundled in the installed app. There is no hosted app page, app backend, ChatGPT sign-in, or localhost development server needed on the phone. The app downloads public timetable HTML directly from FERIT using native HTTP and parses it on the device.

Study/year, per-subject LV groups, personal entries and edits are saved in native Preferences on the phone. Fetched weeks are saved in native Preferences and mirrored in WebView storage. Existing WebView-only cache entries are migrated when read. Internet is needed for new or updated FERIT timetables. Computer and phone choices do not sync. FERIT/AAI automatic membership lookup is not implemented.

## Prepare the project

Use Node.js 22.13 or newer. In this folder:

```sh
npm ci
npm run check
npm test
npm run sync
```

`sync` builds the local interface and copies it into Android and iOS. Do this after changing the interface. Do not add `server.url` to `capacitor.config.ts`; that would replace the bundled interface with a remotely served one.

## Android installation

1. Install [Android Studio](https://developer.android.com/studio), complete its first-run setup, and install Android SDK Platform 36. Android Studio supplies the Java runtime. If building from Terminal, configure `JAVA_HOME` to its bundled JDK and set the SDK path in `android/local.properties` or `ANDROID_HOME`.
2. Run `npm run android` to synchronize the assets and open the native project.
3. Use an emulator, or connect an Android phone with USB debugging enabled and press Run in Android Studio.
4. To make a debug APK in Terminal, run `npm run apk`. The result is `artifacts/FERIT-Moj-Raspored.apk`, copied from `android/app/build/outputs/apk/debug/app-debug.apk`. The build script detects this Mac’s Homebrew Java installation and the usual Android SDK folder.
5. Transfer that APK to the phone and open it to install. If Android requests permission for that file source, approve only the source you are using. This is a development build; preserve the signing key for future updates and use release signing before wider distribution.

The installed app runs without the computer. New schedule downloads and GitHub update checks need a connection. Previously fetched weeks remain available offline.

## iPhone installation

1. Install Xcode 26 or newer from the Mac App Store, open it and finish installing its components.
2. Run `npm run ios`. This synchronizes assets and opens the Xcode project.
3. Select the App target and configure your Apple account/team under Signing & Capabilities, with automatic signing enabled. Change the bundle identifier if your team already uses the default one.
4. Connect your iPhone, trust the Mac, select it as the run destination, and enable Developer Mode when Xcode asks.
5. Press Run. Xcode signs and installs the app on the phone. After installation the computer does not serve the interface or timetable data. Development signing may require renewal; a downloaded ZIP or unsigned IPA cannot simply be tapped to install on an iPhone.

See [Apple's device-running instructions](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices) and [Capacitor's build requirements](https://capacitorjs.com/docs/getting-started/environment-setup).

## Version 1.0.15 — Ponavljački predmeti (build 21)

Open **Postavke → Ponavljački predmeti** to see subjects immediately. Check a subject, choose the teaching types you want to attend, and choose **Spremi odabir**. There is no separate display switch. Only the immediately preceding year of the same study is offered: third-year students can select second-year subjects, second-year students can select first-year subjects, and first-year students have no earlier-year choices.

Each subject offers only teaching types actually observed in its published or saved timetable occurrences, using FERIT's labels (such as PR, LV, AV or KV). Types from multiple available weeks are combined. Subjects with no verified type data do not receive guessed options. You can keep only lectures, only labs, or any available combination. Unchecking the last type deselects the subject. Existing selections from build 20 retain their previously visible types until edited.

These choices filter the day/week timetable and **Ispiti i provjere**. If LV is selected, use **Postavke → LV grupe** to choose the lab group. Personal edits and hidden occurrences retain their FERIT source identity. Choices are saved independently for each primary schedule, and resetting personal timetable changes preserves repeating-subject selections.

The list is discovered from available timetable weeks, with remembered subjects, published types and selections retained locally. Downloaded source weeks and subject/type choices remain available offline; unavailable earlier-year weeks show a separate notice while the current-year timetable remains visible.

Users who installed the earlier 1.0.15 build must download the refreshed APK manually and install over the existing app; the version-based update checker does not offer an equal-version update.
